# P0 工程收尾与兼容决定（2026-09-13）

本轮只使用本地 fixture、mock transport。没有真实语料、自然生成、Docker Judge、benchmark、付费请求或发布。

## 输入与构建边界

`scripts/prepare_authored_corpus.py` 的 `assemble_authored_corpus` 接受冻结 selection、完整 ProblemRecord 映射、CandidateReviewArtifact 映射、现有 authoring specs 和源码字节映射。先对齐每题 record/review/raw-row hash，再校验两处唯一替换的 mutant、四阶段 reasoning、15 格 paradox。通过既有 bundle/corpus lint 后才独占创建输出目录。

CLI 接受 `--selection`、`--records-dir`、`--reviews-dir`、`--out-dir`；records 目录必须包含完整 ProblemRecord JSON，reviews 目录必须包含 CandidateReviewArtifact JSON，不能把公开 authoring-inputs 当成完整记录。CLI 加载同目录的两份规格，禁止覆盖输出。105 项只是自编标签，Judge 尚待执行；60 natural 仅为 pending 配置和 A 中的身份预留。

整个输出目录 0700，文件 0600。完整题目记录仅在 `private/problem-records`；oracle 是已有内部 bundle 的一部分，不能作为公开 trace、generation input 或对外报告发布。authoring provenance 只有公开题目/spec/source hash，并明确 `human_review_performed=false`。所有生产输出失败后保留，换新路径处理，不清理或覆盖。

## A/B 与请求

Python/CLI 资格入口要求 A/B；shell 使用 `HY3_FORMAL_PRE_RUN_INTENT` 和 `HY3_FORMAL_MATERIALIZED_FREEZE`，缺完整输入退出 3，验证不一致退出 2。Compose formal-readiness 只读挂载输入根中的 `pre-run-intent.json`、`materialized-freeze.json`。没有运行 Compose/Docker。

FormalNaturalGenerator 验证 A、源清单、运行身份与 105 样本输入后独占创建运行标记。每个 HTTP attempt（含 transient retry 和 schema repair）前重新验证 A 并在同一 500 次账本中持久预占。单个身份不可重新生成，重建相同 run 不能重置预算；失败保留 failure.json。冻结参数精确进入 HTTP 和缓存哈希，显式参数不补隐含默认值；旧客户端未传参数仍保持 reasoning_effort=high。参数不能覆盖 model/messages/response_format 等请求身份。

下一阶段的完整 60 natural materialization、B 操作包、105 Judge 和后续评估共用账本的真实执行仍属于 P1/P2，不能从这些 mock 推导正式结果。

## comparison 和 schema 兼容

默认 exact 时，checker 引用与 comparison 字段仍按历史规则省略，旧 JSON/hash 不变。非 exact checker 参与 bundle hash，comparison 传入 JudgeSourceCase、Judge 调用和 persisted evidence；资格桥对照 pinned review、bundle、case。第二次读取 review 时再次核对 selection 绑定的 review/raw-row hash，拒绝回读时替换。

历史 `FormalQualificationReport` schema `1.2` 保留原字节/hash 读取。新增强制 A/B 字段的报告改为内部 `formal-qualification-v2`；该版本必须同时包含两个 lifecycle hash，旧版本不得夹带它们。读取任何历史报告不恢复资格能力，资格入口仍须同进程验证完整 A/B 链。`NaturalMaterializationManifest` 的可选生命周期字段在缺省时省略以兼容旧 hash；正式 A/B 路径必须匹配真实 intent/benchmark。未修改共享 `contracts.py`。
